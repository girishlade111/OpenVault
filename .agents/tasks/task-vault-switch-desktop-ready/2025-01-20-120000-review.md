# Switch vault button and frameless window title bar

This change adds a "Switch vault" button to the Ribbon that calls `closeVault()`, allowing users to return to the VaultPicker after opening either the demo vault or a local folder. It also introduces a title bar drag region in VaultApp (displaying the vault name) for Electron frameless window support, and makes the BrowserWindow configuration platform-aware: `hiddenInset` on macOS, `frame: false` on Windows/Linux.

Watch for: On Windows and Linux, `frame: false` removes all native window controls (minimize, maximize, close) but no custom controls are provided (confirmed). The title bar drag region is always rendered, consuming 32px of vertical space even in non-Electron browser contexts (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The vault switching flow is straightforward: `closeVault()` resets store state to null, the root page component re-renders VaultPicker, and from there the user can pick a new folder or re-enter the demo. However, `closeVault()` cancels any pending debounced save timer without flushing, so a fast edit-then-switch sequence can discard the last write.

The frameless window story is incomplete on Windows and Linux. macOS `hiddenInset` preserves the native traffic-light buttons, but `frame: false` on Windows/Linux strips all chrome including window controls, and no replacement UI is provided. Users will need Alt+F4 or a taskbar right-click to close the window.

The title bar drag region unconditionally renders in all environments, costing 32px of vertical space in browser contexts where the drag property is inert.

## Missing window controls on Windows and Linux

The platform branch in `main.js` sets `frame: false` for non-Darwin platforms. On macOS, `hiddenInset` preserves the native close/minimize/fullscreen buttons, but `frame: false` on Windows/Linux strips all window chrome.

```js
if (process.platform === 'darwin') {
  windowOptions.titleBarStyle = 'hiddenInset';
} else {
  windowOptions.frame = false;
}
```

The custom title bar div in VaultApp has `WebkitAppRegion: 'drag'` across its entire width and contains only a text span — no buttons with `no-drag` regions. On Windows, users expect minimize/maximize/close buttons in the top-right corner. Without them, the only way to close is Alt+F4 or the taskbar context menu. This is a blocking gap for "desktop ready" on Windows/Linux. (confirmed)

## Vault switch lifecycle and pending writes

`closeVault()` calls `clearTimeout(saveTimer)` before resetting state. If a file edit triggered the debounced save timer but hasn't flushed yet, the pending write is discarded along with the `contentCache`.

```ts
closeVault: () => {
  void clearPersistedRootHandle();
  if (saveTimer) {
    clearTimeout(saveTimer);
    saveTimer = null;
  }
  set({ handle: null, rootDirHandle: null, manifest: null, workspace: null, contentCache: {}, ... });
},
```

If the timer debounces a `writeFile` call, a user who edits and immediately clicks "Switch vault" loses the last buffered content. The window is the debounce interval (likely short), but the data loss is silent. (likely)

## Title bar in browser contexts

The drag region div renders unconditionally:

```tsx
<div
  className="h-8 flex items-center px-4 shrink-0 bg-sidebar border-b select-none"
  style={{ WebkitAppRegion: 'drag' } as React.CSSProperties}
>
  <span className="text-xs text-muted-foreground truncate">{vaultName}</span>
</div>
```

In a standard browser, `WebkitAppRegion` is ignored, so the div is inert but still consumes 32px of vertical space. The bar's primary purpose (drag region) is irrelevant outside Electron. (confirmed)
